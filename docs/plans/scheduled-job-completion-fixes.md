# Scheduled task completion fixes — 2026-09-28

Scope: desktop scheduling, worker execution, watched-browser tab selection and task instructions. No mobile wiring or dependency changes.

## Observed failure

The supplied Instagram transcript records `spend.tokens=63472` against a model-chosen `maxTokensPerDay=60000`, then `lastStatus=stopped-budget`, `enabled=false` and `pausedReason=budget`. Input context is counted again on each model round, so the worker stopped before its next browser step. The foreground had already observed the rendered profile, but that did not prove the scheduled worker finished.

The old runtime also imposed three active minutes, 24 tool rounds and 60 tool calls. Clicking a watched job tab called the same adapter selection method used by the worker and invalidated its refs. The live repro read `Profile /one` when the worker should still have read `/two`.

## Changes

- Regular desktop jobs default to `executionPolicy=complete`: record usage without token, time, run-count or fixed tool-count/search-count cutoffs. Heartbeats and explicitly bounded jobs retain their limits. Cancellation, repeated calls with no progress, provider failures and real human-input requirements remain active.
- Existing regular desktop definitions normalize to completion execution; old budget-paused jobs remain paused until Resume. Run now can execute a paused task without enabling its recurring schedule. A successful manual run reports success.
- Job scopes opt into independent preview selection. Preview capture resolves a page without changing the worker target; watched-tab changes preserve refs. Completion proof captures the worker's page and pixels independently from the preview cache. Foreground selection behavior stays intact. Takeover input targets the preview tab and remains an explicit pause/handback flow.
- Shared model guidance asks for a standalone objective, exact target, known method, steps, completion evidence, comparison state and output. Details/editor display the exact prompt rather than the short card description.
- Fresh workers receive the last successful result as historical context. Failed runs do not overwrite it, and persistence/export scrubbing applies to the new state as to other job data.
- Malformed credential-field selections return fixed correction guidance and fresh refs before any vault read, password dialog or fill. The model chooses valid username/password refs and `submit_ref` on its next native call. Origin checks and uncertain action failures still stop; this is only recovery from a selection rejected before private access.

## Limits

The app must stay running and the machine must be available. Completion execution does not make a provider's own context/output/rate limits unlimited. A real CAPTCHA/MFA step needs foreground input. The supplied Instagram reading is user evidence; this task's controlled authentication fixtures do not certify every live public site's behavior. Signed installation/auto-upgrade, other OS and real sleep/startup remain outside the live coverage here.
