# Browser Booking Skill

Use this skill for flight, hotel, product checkout, calendar booking, or similar multi-step booking flows.

Booking workflow:

1. Start with `browser_workflow_start` using the relevant workflow type and the user's parameters.
2. Use `browser_workflow_step` to establish the site, snapshot, page state, and first checkpoint.
3. Use `browser_snapshot` to read fields, result cards, forms, filters, modals, and disabled controls.
4. Use `browser_find_element` for ambiguous fields such as origin, destination, dates, passengers, class, guests, checkout, or continue controls.
5. Use `browser_type` and `browser_wait_for` for autocomplete fields, then snapshot again to read suggestions before choosing.
6. Use `browser_network_log` or `browser_intercept_start` before and after search submission when result data is API-driven.
7. Use `browser_workflow_checkpoint` after search results, selection review, passenger details, payment-page arrival, and confirmation.
8. Use `browser_frame_list`, `browser_frame_switch`, and `browser_frame_snapshot` for embedded payment or third-party checkout forms.
9. Stop before final payment, booking confirmation, or purchase submission unless the user explicitly confirmed that exact action.
10. Use `browser_workflow_recover` when the expected page state fails, then report whether retry, back, checkpoint, or escalation was used.

Do not claim a booking is complete without a confirmation page, confirmation number, saved screenshot, or equivalent browser evidence.
